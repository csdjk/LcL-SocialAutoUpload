# 一键投稿与结果回读

## 使用

今日待发布中，先确认每个平台的账号与标题，直接点击该卡片的「投稿」。当前编辑的文案会随请求一并保存在任务中，不必先保存草稿、勾选平台、再点击批量发布。简介、话题、声明与封面设置收在展开区域，保存草稿仍作为可选操作保留。

视频号默认选用「视频画面」封面，页面显示该模式，不会拿自定义封面缩略图误导用户。实际投稿仍须确认官方页面已生成可见、已加载的封面图片。可选择「自定义封面（严格检查）」，横竖封面必须设置成功才会继续，不会暗中降级或忽略失败。封面入口会检查所在编辑器页面、可见弹窗、弹出的上传选项以及稍后创建的文件控件。

## 视频号流程

1. 在本次实际使用的独立 Edge 会话中检查登录和后台作品，不再由另一个 Chrome 会话决定一键投稿的登录状态。
2. 投稿前通过官方页面自然加载的内容列表回执，检查当前账号、北京时间同一期日期、完全匹配的较长简介与实际作品 ID。已有唯一匹配作品时不再上传；存在多个匹配或无法完整读取当日结果时停止，不猜测。
3. 上传视频，填写文案和平台要求的 AI 内容声明，处理封面及短标题。卡片展示当前步骤。
4. 最终发表仅执行一次正常点击，不强制点击、不删除遮挡层，也不按“按钮消失”“跳转页面”判断成功。
5. 点击后回读官方内容列表，找到实际作品 ID 才显示「后台已有作品」。它表示后台存在作品，不声称审核已通过或公开可见。

原账号的扫码、手机确认或官方身份验证仍需本人完成。平台安全要求不会被跳过。

## 失败与重试

明确记录最终发表尚未尝试的失败，会保存 `submission_started=false` 的本地阶段证据并允许手动重试。该证据不等价于“从未上传媒体”，也不声称官方草稿箱里没有暂存内容。每次重试仍先查后台重复作品。

最终发表已经尝试但结果不明，继续保留防重发锁，主按钮改为「同步后台结果」。它只读取后台和更新本机结果，不上传、不重新点击发表，也不因为一次查无结果便自动解除历史任务锁。人工核对保留为备用。

同一任务的执行器使用 SQLite `run_claims` 唯一键防止并发重复执行；投稿预约继续使用原有同日期、平台、账号及跨账号历史保护。

## 接口与数据

- `POST /daily/publish-one`：显式本机操作，提交一个平台及当前文案、预期账号 ID、封面方式。
- `POST /daily/sync-result`：根据原任务账号回读结果，记录真实作品 ID。版本变化或不同作品 ID 不覆盖。
- 两个接口均要求本机来源和 `X-SAU-Local: 1`；响应不包含登录凭据。
- 已有账号、发布配置和原任务身份不会因浏览器登录或回读而自动换绑。
- 今日待发布的资源校验使用短时文件指纹缓存，避免轮询重复读取整个视频；正式投稿预约仍完整校验文件哈希。

## 本轮验证及边界

工程内包含两套浏览器驱动的离线回归、提交边界、查重匹配、并发、重试及实际前端到临时数据库的接口测试。真实视频号后台回读已找到 2026-09-24 20:37:50 的同内容作品并取得 ID；这不证明 22:12 的失败重试本身成功。

本轮未新上传或发表视频。自定义封面在官网上传后的完整保存仍未进行真实投稿验证；默认视频画面模式不依赖该编辑弹窗。不会将离线页面测试描述为官网投稿成功。
