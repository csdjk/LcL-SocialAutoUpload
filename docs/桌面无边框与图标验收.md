# 桌面无边框与图标验收

日期：2026-09-27。

## 改动

- 用统一的蓝色播放图标替换 Python 窗口图标，覆盖窗口、托盘、网页标识。ICO 包含 16、20、24、32、40、48、64、128、256 像素版本。
- 设置独立的 Windows 应用标识 `LcL.VideoPublisher.Desktop`，避免与普通 Python 窗口共用任务栏分组。
- 桌面窗口启用无边框和阴影。原页面顶部栏容纳最小化、最大化／还原、关闭按钮，品牌区域和当前页面名称区域可拖动，双击切换最大化。
- 关闭按钮隐藏到托盘，保留后台任务；真正退出仍使用托盘菜单。弹窗打开时窗口按钮仍可操作。
- 通过指针捕获持续跟踪八个边缘／角落和顶部栏的拖动，在 Windows UI 线程更新位置和尺寸；最大化时关闭缩放区域，拖动顶部栏会先还原。
- 桌面顶部主题按钮简化为平面样式，滚动条随主题显示；普通浏览器页面不显示桌面窗口按钮。
- 窄窗口下账号表格切换成卡片，避免重新登录等操作被挤出可见区域。

实现使用 pywebview 的 [frameless、js_api、icon 接口](https://pywebview.flowrl.com/api/)，以及 Windows Forms 本机窗口几何接口。

## 实际验证

- 生产构建通过；`tests/test_desktop_window.py` 的 13 项测试通过，覆盖关闭行为、状态同步、八个缩放方向、非法输入、图标路由。
- 原生 Windows / Edge WebView2：用生产桌面入口启动独立验收窗口，在 `http://127.0.0.1:5428/` 只读取页面，禁用该验收进程的后台工作线程。通过页面按钮及事件验证拖动、双击还原、最小化、最大化、隐藏及重新显示。
- 实测窗口 `FormBorderStyle=None`；最大化边界不超出显示器工作区。原生窗口导出的 ICO 与目标 ICO 在 256×256 RGBA 像素上完全一致，进程应用标识核对通过。没有以任务栏截图代替这些检查。
- 原生内容截图由 WebView2 `CapturePreviewAsync` 获取；DPR 1，实际视口为 1304×841、780×560 和最大化时 2560×1392。覆盖今日待发布、账号管理、深浅主题、最小尺寸与弹窗。窗口外壳状态另用原生 API 核对。
- Edge headless 补充页面检查：桌面桥接夹具 1320×880、780×560；普通网页 1320×880、320×568、375×667、390×844；全部深浅主题，共 12 个页面状态及 12 个添加账号弹窗。检查按钮调用、最大化标签、弹窗安全边距、长账号名和横向溢出。

## 2026-09-27：拖动与缩放修复

初版使用 `WM_NCLBUTTONDOWN` 启动缩放，复现显示该路径在当前无边框 WebView2 窗口没有改变大小：右下角连续拖动 90×70 像素后，窗口仍为 1000×700。之前仅断言消息参数的测试不充分。

现在前端捕获完整的 pointerdown / pointermove / pointerup 生命周期，合并桥接繁忙时的中间坐标，并在结束前应用最后一个位置。后端根据起始矩形计算各方向边界，在 UI 线程设置窗口位置与大小，保留对角锚点和 780×560 最小尺寸。顶部拖动区域覆盖全部非按钮区域，移除了旧拖动处理以避免两套逻辑冲突。

验证：

- `tests/test_desktop_window.py` 17 项、`sau_frontend/tests/windowGestures.test.js` 5 项通过，生产构建通过。
- 真实 Windows / Edge WebView2 窗口，通过其 Input 接口注入连续按下、移动、松开事件，测量原生 `Bounds`；未占用实体鼠标。八个缩放方向全部使窗口尺寸按预期改变。
- 右下角：1000×700 → 1090×770；顶部移动：位置 (300,200) → (380,245)；缩小限制为 780×560；从最大化顶部拖动后回到普通窗口。
- `Temp/window-gesture-qa/before.json` 保存失败复现，`after.json` 保存逐项位置与尺寸；`Temp/verify_window_gestures.py` 为复现／回归脚本。
- 运行截图 `Temp/window-gesture-qa/after.png` 来自实际 WebView2 内容捕获，页面 `http://127.0.0.1:5428/#/`，DPR 1、最终视口 780×560；原生窗口位置与大小用 API 单独核对。已检查顶部按钮和缩小后的内容没有横向溢出。
