# B站平台接入

## 默认浏览器登录

添加账号默认使用「浏览器登录」：点击「打开 Edge 登录」，在工具专用窗口完成官方登录后自动获取、验证、转换并保存登录态，无需复制 Cookie。详见 [浏览器登录与自动保存](浏览器登录与自动保存.md)。以下扫码、导入方式仍可备用。

## 使用

刷新本机 Web 页面后，账号管理新增「B站」标签，添加账号的平台列表也包含「B站」。平台编号为 5，原有 1～4 编号不变。

### 扫码

添加账号 → B站 → 填写名称 → 扫码 → 确认。使用哔哩哔哩 App 扫描弹窗二维码并确认。仅在平台确认授权、登录态验证通过、数据库保存完成后提示成功。取消弹窗会结束该登录任务，未确认的尝试不会保存账号。

已失效的 B站账号可点击状态重新扫码，更新原记录，不额外创建同名账号。二维码过期、平台拒绝和网络失败会显示错误，可重新获取。

### Cookie / JSON 导入

添加账号 → B站 → 导入登录态，可粘贴自己在 B站网页中取得的完整 Cookie，或选择 Cookie 数组、Playwright storage_state、biliup 登录态 JSON。已有账号的「上传Cookie」使用相同校验入口。

导入需要 SESSDATA 和 bili_jct。工具只访问 B站验证及授权接口，将有效网页会话转换为现有 biliup 投稿内核所需的登录信息；不会跳过平台安全验证，也不会自动投稿。不同网站的 Cookie 会被过滤。验证失败不覆盖旧记录，临时文件会清理。

凭据只在本机提交，不进入应用日志、不回传给前端，保存在 Git 已忽略的 cookiesFile 目录。不要把 Cookie 或登录态文件发到聊天、群或代码仓库。

## 普通发布中心

发布平台选择 B站后，可选择已验证的 B站账号；填写分区 ID，明确选择自制或转载，转载需填写来源，至少添加一个标签，可填写简介。定时使用界面的 HH:MM 和延后天数；不满足提前时间要求会在上传前报错。

发布分发沿用现有 biliup 运行时，通过参数数组调用，不拼接 shell 命令。账号、文件目录、视频扩展名、分区、类型、标签、时间会在任何上传前统一校验。同账号并发投稿被阻止，不自动重试。流程返回不等同于审核通过或公开发布，请到 B站创作中心核对稿件。

当前普通发布入口不提供 B站自定义封面、AI 声明或仅存草稿操作；需要这些设置时使用官网。新增 Web 账号不会自动改写「今日待发布」的日报账号绑定、定时任务或 publishing 配置。

## 实现与验证

- 登录及状态：uploader/bilibili_uploader/web_login.py、myUtils/credential_import.py、myUtils/auth.py。
- 发布适配：uploader/bilibili_uploader/web_publish.py、sau_backend.py。
- 前端：共享账号映射与表格、通用凭据导入组件、发布中心及概览。
- 登录协议与 biliup LoginInfo 格式参考上游实现：https://github.com/biliup/biliup/blob/master/crates/biliup/src/uploader/credential.rs 。
- 投稿参数以本机 biliup upload --help 验证。

本次相关后端回归 146 项、前端测试 32 项通过，生产构建通过。Edge 实际验证了平台入口、真实二维码显示（约 1.14 秒）、取消清理、导入格式错误、JSON 入口、发布账号筛选与切换清空。发布账号的 UI 测试使用仅存在于浏览器响应中的模拟记录，未向真实账号库添加测试账号。

真实 B站账号扫码确认、有效 Cookie 导入及实际视频投稿仍需本人操作验证。本次开发没有实际上传或投稿，现有抖音和视频号记录保持不变。
