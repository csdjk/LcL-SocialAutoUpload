# 桌面版、普通视频与自动排程

桌面版在 Windows 本机运行，提供工作窗口、系统托盘和独立后台执行器。它与“今日待发布”、Codex MCP 共用 `db/daily-jobs.db` 投稿账本。窗口关闭后会收进托盘；从托盘选择“退出程序”会停止领取新任务。已进入平台提交阶段的任务会完成当前调用。电脑休眠、关机或退出登录后不能保证继续运行；再次启动会恢复尚未执行的任务，已提交但结果不确定的任务先核对，不自动重投。

## 安装与启动

在项目根目录执行：

```powershell
uv sync --extra web --extra mcp --extra desktop
cd sau_frontend
npm install
npm run build
cd ..
.\启动桌面发布工具.ps1
```

也可双击 `启动桌面发布工具.cmd`。启动器检查依赖后在后台启动桌面进程，重复点击会唤醒已有窗口；本机唤醒请求绕过系统代理。桌面版依赖 WebView2；登录和平台页面仍可能打开各自的浏览器窗口。系统托盘可以重新打开工作台、暂停或恢复领取新任务、退出程序。默认使用 `127.0.0.1:5409`；端口已有服务时，在后续 20 个端口中寻找空闲端口，不停止原服务，两者共用投稿账本。可用 `-Port` 指定起始端口，或 `-CheckOnly` 仅检查依赖与空闲端口。每次启动日志保存在 `db/desktop-launch-*.log` 和对应 `.error.log`；失败时启动器会给出日志路径。

## 普通视频

导航保留“今日待发布”作为首页；“内容库”提供“普通视频”和“素材文件”两个分类，“设置”包含自动排程与关于信息。旧页面地址会跳转到对应分类。

在“内容库 → 普通视频”导入本机 MP4，填写标题、简介、话题和可选封面。工具校验文件与时长，生成横竖封面，将资源复制到 `db/imports/`；相同视频内容只保留一份。导入后可用通用文案一次填入三个平台，再按需展开平台专属字段，选择立即入队或预约带时区的未来时间。单个视频最大 2 GiB；更大的文件需要扩展导入实现。普通视频不依赖 AI 日报生成脚本，也不受“只能发布今日资源包”限制。

“任务中心”按作品归组显示所有来源的任务，需处理和进行中的作品优先展示，已公开发布的记录默认收起。每个平台的投稿记录、进度和核对操作仍独立保留。排队、投稿中、审核中、已发布、失败和结果不确定是不同状态。平台接口只返回受理或处理中时，不能据此认定公开发布。点击“从平台回读”只核对原作品；遇到无法自动确认的通道，在原账号官方内容管理中核对，再记录人工结果。不要为不确定任务新建同内容投稿。

任务中心和“今日待发布”按实际事件显示准备、上传视频、完善信息、提交、平台核对五个阶段，并自动刷新。仅当官方上传页面明确显示可唯一识别的百分比时，上传段才显示对应数值；否则使用动态等待提示，不把经过时间换算成虚假的上传百分比。完成上传或平台受理后，进度不会自动代表公开发布。

## 自动排程

“自动排程”默认关闭，各平台也默认关闭且标记未验收。需要先用真实目标账号逐平台验证文案字段、封面、实际提交及结果回读，再在界面勾选对应平台“已用真实账号验收”，启用平台并保存总开关。工具每约 30 秒检查一次北京时间当天的完整有效日报资源包，在配置的时间窗口内为每个启用平台最多创建一个任务；平台访问未就绪时记录等待原因，不会借用昨日内容。截止时间随任务写入，队列延迟超过截止时不再启动该次投稿。

视频号自动投稿还受桌面版平台验收设置约束。三个平台共用去重账本；已有人工或 MCP 投稿、处理中或结果不确定时，自动排程不会另起一次同内容投稿。旧版 06:00 Codex 自动任务若仍启用，它与新排程可能同时发现同一资源包；账本会阻止重复投稿，但建议在切换到桌面排程前核对并停用旧计划，避免重复触发和混淆状态。

当前自动回读覆盖具备授权与作品 ID 的抖音官方 API，以及启用并验收后的微信视频号后台。B站及浏览器通道的审核结果可能仍需在官方后台人工核对。当前实现和本机模拟验证不代表三个真实账号已通过投稿、审核或公开可见性验收。

## 数据与排查

- `db/automation.json`：自动排程设置；包含各平台验收开关。
- `db/daily-jobs.db`：任务、队列、结果证据和自动排程事件。
- `db/imports/`：普通视频及导入封面；删除前先检查任务与历史关联。
- `db/daily-jobs.worker.log`：后台执行器错误日志。

这些本机数据不应提交到 Git。平台登录态继续使用现有账号管理，不能把令牌或 Cookie 放入文案、资源包或反馈截图。
