# AI 日报每日交付与发布

`social-auto-upload` 的“今日待发布”页读取制作端 `发布输出/YYYY-MM-DD/rNNN/package.json`。页面只自动选择北京时间当天最新且校验通过的版本；旧版和昨日视频不会顶替当日内容。正式资源包只读，手动文案保存在本工具的 SQLite 草稿中。

首次将 `docs/daily-settings.example.json` 复制为 `db/daily-settings.json`，填写本机资源根目录、各平台已核实账号 ID 与 CLI 登录别名。视频号可改用本工具账号库 `db/database.db` 中对应的 `user_info.id` 作为 `web_account_id`，其登录文件仍保留在 `cookiesFile/`，无需复制凭据。此文件和 `db/daily-jobs.db` 均不纳入 Git。B站和抖音沿用各自的 `access_status` 配置。视频号手动投稿则根据绑定的工具账号、保存的登录状态及登录文件判断是否可选，不再受历史 `blocked_browser_policy` 标记或制作工作区 `publishing.json` 中旧的浏览器状态限制；`enabled: false` 仍可主动关闭手动投稿。实际提交仍会重新检查平台登录态、封面及内容声明，平台要求的验证需要本人完成。

```powershell
python -m daily_publish import-legacy
python -m daily_publish today
```

第一次启用前导入制作工作区的 `publications.json`，同日同平台同账号的旧记录会合并，已提交、审核中、结果不明及已发布均阻止再次投稿。账号换绑时仍检查旧账号记录。不会自动补发历史期次。

新服务提供 `GET /daily/today`、`GET /daily/asset/<日期>/<版本>/<资源键>`、`PUT /daily/draft`、`POST /daily/submit`、`GET /daily/task/<任务ID>` 和 `POST /daily/reconcile`。任务在上传前先写入 SQLite，刷新页面可恢复；进入上传器后的异常或缺少远端回执的返回先标为“结果待核对”，需凭平台内容管理中的真实作品 ID、审核状态及链接核对。只有确认失败且没有远端作品的任务才允许重新提交。每日自动化通过统一服务提交已授权且检查通过的平台；结果未知的原任务保持禁止重复投稿。

## 每日六平台工作流

唯一日程是 Codex 的 `ai-06`：每天北京时间 06:00 制作并投稿。2026-10-03 起目标为抖音、B站、视频号、今日头条、YouTube、快手。小红书已从今日发布及每日自动投稿移除，账号、草稿与历史保留。发布工具内置自动排程继续关闭，避免两个调度器重复触发。

合格资源包准备完毕后，调用 `local-video-publisher.get_daily_package` 获取当日版本、`selection_id` 和 `publishable_platforms`。将 `douyin,bilibili,wechat_channels,toutiao,youtube,kuaishou` 与可投稿平台取交集，再调用 `publish_daily`，随后用 `get_publish_task` 和 `sync_publish_result` 回读原任务。不得用昨日包、重新入队或切换通道补救结果不明的投稿。

交付器仍可生成兼容七平台的文案和九张封面，但每日只投稿上述六个目标，不自动补投小红书。小红书使用独立的 1080×1440 封面、1–20 字准确标题及不超过 10 个当日相关话题；标题过长应编辑，不能直接截断事实限定。上传后核对自定义封面与原图，再执行提交。

B站沿用 biliup 接口，默认不强制可选 AI 声明；YouTube 使用官方 Data API。抖音按现有可用授权和封面能力选 API 或浏览器；视频号、今日头条、快手使用现有浏览器通道。任务开始后固定通道；API 超时不能换浏览器重投。

逐平台检查实际账号、登录态、封面、原任务与远端结果，故障只暂停对应平台。YouTube 视频已公开但自定义封面待处理时，仅补设原作品封面，禁止重复上传。分别报告已提交、审核中、已公开、需要处理及未执行，不能将工具退出或页面跳转视为公开发布。B站时间定位评论、置顶及合集归类仍是投稿后的独立步骤。

## 原任务核对

通过 `sync_publish_result` / 页面“同步后台结果”优先获取原账号的官方后台证据。人工核对接口 `python -m daily_publish reconcile --task-id <任务ID> --state processing|published|failed|unknown|needs_action --evidence-file <JSON>` 只更新原账本，不上传视频。证据至少包含 `platform`、`account_id`、带时区的 `checked_at` 和实际核对说明 `note`，审核中与已发布需要真实 `remote_id`，已发布另需作品 `url`。确认失败还须记录 `remote_absent: true` 和实际核查依据，才能再次提交；缺少证据保持结果待核对。

## 视频号工具账号与账本标识

视频号已绑定 `web_account_id` 时，不要求再手工填写远端 `account_id`。没有远端标识时，工具使用 `web:wechat_channels:<工具记录ID>` 作为本地草稿与投稿账本键；它不是微信返回的账号标识，不代表已核实远端身份。显式配置过的账号 ID 会继续保留，以兼容已有账本与草稿。重新登录同一工具记录不会改变本地账本键，切换绑定账号仍会触发同日同平台的跨账号投稿保护。

页面的“待发布”表示允许手动发起尝试，不表示作品已经提交或公开发布。实际登录失败、缺失登录文件、平台安全验证以及重复或结果不明的投稿仍按原流程处理。任何配置调整都不会自动触发上传。


## 上传前失败与重新登录

登录检查、账号绑定或资源校验在调用上传器之前明确失败时，任务记为 `failed`，记录 `stage=preflight`、`upload_started=false` 及该次任务未产生远端稿件的本地证据；页面直接显示失败原因和“尚未上传”，不再要求用户填写远端核对表。视频号登录校验未通过时，只有仍指向原凭据的账号记录会更新为异常，避免覆盖同时完成的重新登录。

在账号管理中对原账号点击“重新登录”，由工具弹出的 Edge 完成登录并保存后，可返回手动再次提交；不会自动重发。已进入上传器后的错误仍保持结果未知，不能仅依据错误文字将其放行重试。


## 账号删除重建后：恢复日报发布绑定

账号管理的登录记录与日报的发布目标是两层数据。原视频号记录被删除、随后重新添加时，新账号有新的工具编号，日报不能继续引用已删除的编号，也不能在名称不同的情况下自动替换投稿目标。

在“今日待发布”的视频号卡片点击“选择已登录账号”或“更换账号”，核对当前账号名称和编号，点击“绑定此账号”。该动作只保存发布目标，不会上传、不会提交视频，也不会覆盖当前编辑文案。弹窗显示的是账号管理上次保存的状态，真实登录态仍在提交前校验。绑定接口使用本机来源限制、配置修订号及原子写入，视频号任务执行中禁止改绑。

当旧任务有明确的上传前失败证据（failed、preflight、upload_started=false、remote_absent=true 且没有作品 ID/链接），允许选择新账号后手动重试；原任务身份和失败证据完整保留。其他账号存在上传中、审核中、已发布或不确定结果时仍阻止重复提交。任何历史导入记录的跨账号阻拦保持不变。

重新登录原账号、或明确改绑到已有正常账号后，卡片显示“待重新提交”，旧的登录错误收进“上次任务记录（未上传）”，不再把旧错误当作当前账号刚刚失败。账号记录已删除则显示“请选择发布账号”，而不是反复要求扫码。
