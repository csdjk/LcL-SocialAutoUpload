# 浏览器登录与自动保存

账号管理中，YouTube 使用 [Google 官方授权](YouTube官方授权配置.md)，由系统默认浏览器完成；其余六个平台新增和重新登录默认使用「浏览器登录」，工具保留每个账号的专用浏览器记录。所有入口均无需扩展。

## 操作

添加账号 → 选择平台 → 打开 Edge 登录。无需填写账号名。在新打开的 Edge 窗口内完成平台登录与必要的手机确认、安全验证；工具检测到真实登录状态后自动读取平台昵称、保存账号并关闭该登录窗口。无需打开开发者工具、复制 Cookie 或准备 JSON。

登录窗口是普通的持久化 Edge 窗口，每个平台、账号使用工具专用的独立配置目录。首次使用时在这个窗口完成登录，之后重新打开时复用该目录中的浏览器数据。日常 Edge 的用户目录与工具配置相互独立，因此日常 Edge 已登录不等于工具窗口也已登录。

导出的投稿登录态位于项目已被 Git 忽略的 `cookiesFile` 中，完整浏览器配置保存在同样被忽略的 `db/browser-profiles/` 中。关闭窗口会保留浏览器数据；平台登录态仍可能过期，要求再次验证时，通过账号行的「重新登录」更新原记录。专用配置目录不应提交 Git 或共享给他人。

账号与浏览器配置的关联保存在账号数据库的 `browser_profiles` 表中，投稿刷新凭据文件不会丢失该关联。旧版本凭据中已有的配置标识会在下次浏览器登录保存时迁移。原来通过扩展导入的账号保持有效记录，但如果从未使用工具的浏览器窗口，首次切换时需要在该窗口登录一次。

## 备用入口

支持扫码的平台添加新账号时仍可选择「界面扫码」。B站、抖音保留「导入登录态」及 Cookie／JSON 入口，B站还保留扫码重新登录方式。YouTube 使用官方 OAuth；下文浏览器配置、Cookie 与控件检测说明适用于其余平台。历史验证记录反映当时版本。

B站浏览器登录态会自动转换成现有 biliup 投稿模块所需的格式并校验授权；仅网页登录完成但投稿授权未完成时不会保存成正常账号，也不会自动投稿。

## 取消、错误和隔离

取消工具弹窗、关闭登录窗口或等待超时，会结束该登录任务；未成功的尝试不会创建账号或覆盖旧投稿凭据，浏览器本身已产生的数据会保留在专用配置中。每个平台、每个待添加或更新账号独立打开窗口，重复打开同一个账号会提示先结束上一次；文件锁也阻止网页版和桌面版同时打开同一配置目录。

只有已登录后台的明确控件和会话状态同时满足条件时才自动保存；仅页面跳转、空白页或手机已扫描消息不算登录成功。平台安全验证由用户本人完成，工具不会自动跳过或处理挑战。

重新登录使用原账号 ID 和事务条件更新，校验期间账号被删除或换了新凭据时，不会把旧结果覆盖回去。会话中只有所选平台的 Cookie 和浏览器存储进入登录文件；凭据内容不发送到聊天、不打印在应用日志、不放入 URL。
