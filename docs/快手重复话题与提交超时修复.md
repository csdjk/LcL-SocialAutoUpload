# 快手重复话题与提交超时修复

## 2026-09-27 现场与根因

原任务 `59815652-8053-498c-aa8b-12d9026adc58` 完成视频上传与封面设置后，等待旧地址 `?status=2&from=publish` 的导航超时。原账号官方作品管理与列表回执多次确认 0 个作品，且列表为全部作品、空关键词、结束游标 `no_more`。

加入诊断后的受控复测 `df57019b-655e-4f3c-a40e-92c84aa1ea2b` 捕获真实平台报错：**内容发布失败：话题标签数量超过上限：4**。旧正式包的简介已经包含三个话题，上传器又追加同一组三个话题；页面提交校验被拒后不会跳转，旧代码把实际错误隐藏成了导航超时。

证据：`ks_debug/submit_once_20260927_160809.png`（1280×720，实际 Edge 投稿页面），同名 HTML；`Temp/kuaishou-submit-fix/manager.png`（1440×1000，只读 Headless Edge 官方内容管理）。仅作为实际现场证据，无参考图还原或相似率要求。

## 修复

- 快手视频通道把简介内话题与话题字段合并、去重，正文去掉重复话题，再由上传器追加一次。保留当前通道最多三个话题的兼容边界；超过时在上传前明确提示，不静默截断。
- 提交后等待异步确认弹窗，每个最终操作最多一次；按官方域名与作品管理路径识别跳转，不依赖查询参数顺序或全页 `load`。
- 读取页面实际校验错误，保留原始原因、截图和 HTML。结果不明仍禁止自动重投；进入作品管理不等于公开发布。
- 保留两次失败任务与核对证据，只有平台明确拒绝且原账号后台确认无作品后才进行修复验证。

## 验证

真实浏览器隔离测试先复现了延迟确认弹窗和查询参数变化导致的旧超时。修复后提交、原任务去重保护、标签合并、上传前超量拦截和错误现场相关测试共 22 项及 3 个子测试通过；原确认弹窗测试另 2 项通过。未修改页面布局。

后台回查、账本和平台相关回归另通过 92 项及 3 个子测试。新增提交后读取官方作品列表：审核阶段的 publishId 是临时投稿回执；审核后该字段可能为 0，必须使用实际 workId，不能把 0 当作作品 ID。只在明确的已发布、审核通过与公开状态同时满足时记录 published。
