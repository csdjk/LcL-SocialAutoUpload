## 修复内容

### B站

- 删除页面预检、后台入队对 `ai_declaration_fields` 的强制门禁，默认配置缺失时不传该可选声明。平台自行添加的 AI 标识仍由平台决定。
- 新增按账号保存的分区记忆。首次读取该账号最近成功 AI 日报分区；本次恢复为「知识 / 野生技能协会」，ID 122。界面可按名称搜索选择。
- biliup 子进程不再继承其不支持的 SOCKS 代理；保留显式代理参数和 HTTP 代理，并记录直连原因。
- 上传后优先保存返回 ID；缺少 ID 时按原账号、日期、完整标题回查。多个匹配、列表不完整均不能证明成功或不存在。
- 公开状态另用不带账号 Cookie 的公开视频接口确认；接口失败保留收稿状态并记录原因。

### 视频号

- 排除无界子应用隐藏 iframe 的重复节点；弹窗筛选和元素下标均以实际可见节点为准。
- 使用横版封面实际卡片区域，处理推荐封面浮层、直接编辑入口和「编辑分享卡片」弹窗。
- 横版、竖版分别上传对应图片，处理裁剪并验证保存后的预览。任何一步失败都停在最终投稿之前。
- 登录及投稿使用标准 Playwright 驱动；两个自定义封面在真实官方页面保存成功，后台已读到本次作品。

### 头条和抖音

- 头条从当前「创作 → 视频」入口进入，支持新标题字段、上传成功状态、本地封面上传、多步裁剪和二次保存确认。
- 头条按 16:9 适配完整封面；固定发布栏可能遮挡短窗口中的声明控件，声明滚动到可见中心后再点击。实际投稿采用 1440×1000 窗口。
- 头条读取官方页面自身的内容列表响应，保留字符串作品 ID、创建时间和原始审核状态；官方预览链接不冒充公开链接。
- 抖音改为标准 Playwright，浏览器关闭失败不覆盖原错误；保存投稿阶段、回执和诊断截图。最终按钮只点击一次，检测错误提示和后续确认/安全验证，需本人处理的确认保留在官方窗口。
- 抖音补投完成上传、声明、封面、单次最终发布及内容列表回查。回执保留审核和可见性字段，分享链接移除设备及追踪参数；本次回查 `self_see=true`，没有标记为公开。

## 通道及配置

- 通道在入队前选择并保存，执行前核对账号和通道配置，任务中途不切换。
- YouTube 入队前校验视频、封面格式与大小、授权范围，必要时刷新授权并读取目标频道；不创建视频。上传开始前再检查一次。
- 抖音 API 校验 `video.create.bind`、账号、授权期限、文件大小和文案长度。当前资源包要求 AI 声明及自定义封面，保留浏览器通道。
- YouTube 配置见 [官方授权配置](YouTube官方授权配置.md)。未经 YouTube API 合规审核的项目可能只能上传私享视频；OAuth 验证与 API 合规审核不是同一件事。
- 头条继续使用浏览器，官方 API 需取得应用授权后另行接入验收，当前不标记为可用 API。
- 新平台的每日自动发布没有因这次手工验收自动开启。

网页、桌面和后台均使用此仓库；增加代码版本指纹，更新后带此保护的旧版本服务拒绝新任务并提示重启。收尾时网页 5409、桌面 5410、新 MCP 实例均返回指纹 `abef7eadb4383e4d`，后台执行器已重启。本轮正式提交通过新启动的同仓库 MCP stdio 实例完成。Codex 当前会话原来已建立的 MCP 连接仍是旧版本（三个平台），需要重新连接；该旧连接尚无新保护，不能把新实例通过误报为旧连接已热更新。
